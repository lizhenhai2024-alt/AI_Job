# AI Job 发现 / 情报库规划

## 产品目标

AI_Job 只解决一个上游问题：**怎样尽可能完整、及时、可追溯地发现 2027 届岗位，并把可靠情报交给最终看板？**

最终“值不值得投”不在本仓库计算，由 `campus-job-board` 统一负责。

## 两库架构

### AI_Job：岗位发现 / 情报库

负责：
- 五大渠道岗位发现
- 公司官方招聘入口与 ATS 识别
- 2027 届证据
- 截止 / 关闭状态
- 原始来源、职位级链接、发布时间
- 岗位字段标准化
- 跨来源核实与去重
- 明显噪音过滤
- 抓取标签、语言硬要求等情报线索

不负责：
- S/A/B
- 匹配度
- 最终岗位方向
- 公司匹配度
- 是否值得投

### campus-job-board：最终判断 / 展示库

读取 AI_Job 的岗位情报，统一执行候选人适配、岗位方向、公司匹配和投递价值判断。

## 五大获取渠道

1. 公司官方校招官网 / ATS 系统
2. 高校就业信息网官方简章
3. 招聘平台官方账号
4. 牛客 / 脉脉官方内推帖
5. 公司官方公众号 / 微博校招公告

## 下一阶段优先级

### P0：来源覆盖
- 扩充高校就业网来源池至 30+ 高校
- 增加猎聘 / 51job / 智联 / 应届生求职网官方发布发现
- 增加牛客 / 脉脉认证内推信息发现
- 建立公司公众号 / 微博公告入口清单

### P0：交叉核实与去重
- 同一公司 + 岗位 + 城市合并为一个职位实体
- 保留 `sourceEvidence[]`，而不是删除重复来源证据
- 官方职位级来源覆盖二手投递链接
- 公告级信息与职位级 JD 分开保存

### P1：数据质量
- 职位详情链接有效性检查
- 截止日期冲突处理
- 招聘批次 / 届别冲突处理
- 合并岗位标题自动拆分为具体职位
- 小语种硬要求线索结构化

### P1：与最终看板契约
- 固定 `live-jobs.js` Job Schema
- 增加 schema version
- 对最终看板依赖字段做自动契约测试
- 禁止 AI_Job 输出最终 S/A/B 或候选人匹配分
