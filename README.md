# AI Job

面向 **2027 届英语专业本科生校招** 的岗位发现 / 情报库。

> **三库职责固定：**
> - `AI_Job`：负责岗位发现、来源核验、职位级链接、届别/截止/语言/专业要求、完整 JD、薪资、岗位级 HC、招聘流程和公司历史风险等事实与证据。
> - `campus-job-board`：只发布风险情报契约，不计算个人 Match / Competition / Offer Reachability。
> - `CareerPilot`：唯一候选人最终决策与展示入口，负责 Eligibility、Match、Capability、Career Fit、Competition、Offer Reachability、First-job Value、Company Top3 和投递组合。

## AI_Job 不做什么

本仓库不维护第二套候选人评分，也不输出：

- S / A / B 等级
- 0–100 候选人匹配度
- Career Fit / Capability / Competition / Offer Reachability
- 公司匹配度
- “主投 / 冲刺 / Offer池 / 低优先 / 不建议”等最终结论
- 公司“黑名单分数”

候选人最终判断统一由 `CareerPilot` 完成。

## 采集范围：面向英语专业本科生，不做全职位镜像

AI_Job 的生产岗位池不是“企业所有校招岗位全量备份”，而是面向英语专业本科生求职的**受控岗位情报池**。

### 生产池直接排除

以下岗位在最终 `live-jobs.js` / Query Layer 入库前排除：

- 明显技术专业岗位：软件、算法、前后端、嵌入式、硬件、芯片、电子、电气、机械、结构、工艺、材料、仿真、控制、自动化、研发/开发/技术工程师等；
- 明显专业财会金融岗位：财务、会计、审计、税务、出纳、司库、投融资、投资分析、证券、基金、精算等；
- 法务/律师/法律顾问/知识产权等专业法律岗位；
- 医学、药学、临床、化学/生物专业研发、土木/建筑等明显专业岗位；
- 岗位名称本身不明显专业，但 JD **硬性限定**上述专业背景，且没有英语/语言/市场/管理/国际商务等候选人友好专业作为可选范围的岗位。

### 不应误删

以下情况仍可保留：

- `专业不限 / 不限专业`；
- 英语、外语、语言类、翻译、新闻传播、市场营销、国际商务、国贸、管理类、人文社科等专业可投；
- 技术/财务类专业只是“优先 / 加分”，不是硬门槛；
- 岗位属于项目管理、海外业务、GTM、市场、品牌、运营、跨境电商、供应链、HR、销售/BD、客户成功、国际物流等英语专业可能进入的方向。

这样做的目的是：**在 AI_Job 上游先去掉明确不可投的专业职位噪音，但不在上游计算个人匹配分和投递优先级。**

## 来源策略：公司官网为主，高校为补充

AI_Job **不只保留高校校招**。

生产源优先级：

1. **公司官方校招官网 / ATS 的职位级岗位**：主来源；
2. **高校就业网官方发布 + 明确 2027 届 + 明确公司官方投递入口**：允许作为受控过渡记录，保留 `secondary` 身份和“待官网细化”标记；
3. 招聘平台、内推帖、公众号/微博等：用于发现和交叉取证，不能替代职位级官网核验。

高校就业网负责**补漏和交叉取证**，不是唯一岗位来源。发现同一岗位的公司官方记录后，以官方职位为主记录，同时保留高校来源作为证据链。

## Query Layer

为避免下游每次加载大型 `live-jobs.js`，AI_Job 发布：

```text
jobs/index/jobs.json
jobs/index/companies.json
jobs/by-company/<company>.json
```

主要保留：

`company / title / graduationYear / education / major / language / location / jobDescription / jobRequirements / JD / jdEvidence / roleFamily / skills / headcount / compensation / source / officialURL / publishedAt / lastVerified / deadline`

Query Layer 只搬运岗位事实，不允许出现 Match、Capability、Career Fit、Decision Score、Recommendation 等候选人决策字段。

## 薪资情报

岗位刷新后统一做薪资结构化：

- 保留原始 `salary`
- 生成 `monthlySalary`
- 生成 `annualSalary`
- 保存 `compensation`：月薪上下限、年薪上下限、薪数、来源、可信度和证据片段

规则：

- `15K-25K·14薪` → 月薪 1.5–2.5 万；年薪约 21–35 万（按14薪推算）
- `15000-22000元/月` → 年薪只按 12 薪估算，并明确标注“估算”
- `年薪24-36万` → 年薪直接采用来源值；月薪只做 12 个月等效估算
- `面议 / 未披露` → 显示未披露，不猜数
- 二手来源薪资标记待官网复核
- 不擅自加入未披露年终奖、股票、补贴或绩效奖金

## 公司历史风险 / 实习留用情报

`src/data/company-risk-history.js` 保存可追溯历史事件：

- 裁员 / 人员优化
- 组织重组
- 实习转正 / 留用 HC 风险
- 校招毁约 / 缩招（有证据时）
- 工作强度争议（有证据时）
- 薪酬争议（有证据时）

证据分级：A 一手材料；B 权威转述；C 可追溯社区线索；D 未核实传闻默认隐藏。

风险原则：必须有来源、日期和范围；历史事件不能自动外推为当前全公司状态；AI_Job 不形成公司黑名单或投递结论。

## 获取渠道

1. 公司官方校招官网 / ATS
2. 高校就业信息网官方简章
3. 招聘平台官方账号
4. 牛客 / 脉脉官方内推帖
5. 公司官方公众号 / 微博校招公告

高校目标池配置见 `config/university-sources.json`；高校渠道优先级只决定“搜哪里、搜多深”，不参与 CareerPilot 最终评分。

## 数据处理流程

```text
公司官网 / ATS + 高校就业网 + 其它发现渠道
    ↓
原始来源与职位链接保留
    ↓
2027 届 / 截止 / 关闭 / 正式岗位校验
    ↓
Job Schema 标准化
    ↓
英语专业本科生范围过滤
    ├─ 明显技术专业岗 → 排除
    ├─ 财务/会计/审计/税务/金融/法务/精算等 → 排除
    └─ 硬性专业门槛且无候选人友好专业 → 排除
    ↓
完整 JD / jdEvidence / HC / 薪资事实结构化
    ↓
跨来源核实 / 去重 / 证据保留
    ↓
live-jobs.js
    ↓
Query Layer
    ↓
CareerPilot：唯一候选人最终决策

AI_Job 公司风险底层证据
    ↓
campus-job-board：risk-intelligence.json
    ↓
CareerPilot：风险展示与决策参考
```

## 来源规则

- 企业官方职位级来源优先。
- 高校就业网、招聘平台、内推帖、公众号/微博是发现入口和补充证据。
- 学校官方发布 ≠ 企业官方职位。
- 二手或公告级来源不能替代职位级官网核验。
- 同一岗位多源出现时保留交叉证据。
- 投递链接优先指向公司官方校招官网 / 官方 ATS 的具体职位页。

## 自动刷新

```bash
npm run refresh:jobs
npm run check
```

GitHub Actions 每日自动刷新岗位池。只有岗位池或来源健康状态实际变化时才提交新的数据文件。

## 设计底线

1. AI_Job 是**英语专业本科生校招情报库**，不是全专业岗位镜像。
2. 明显技术、财会金融、法律、医学等专业岗位和硬性专业门槛岗位在生产池入库前排除。
3. 对保留下来的岗位，AI_Job 只提供事实和证据，不计算候选人最终分数。
4. `campus-job-board` 只发布风险契约；`CareerPilot` 是唯一最终候选人裁决层。
5. 公司官方职位级来源优先；高校就业网用于补漏和交叉取证，不做唯一来源。
6. 正式岗位必须可追溯；来源不充分就明确标记“待官网复核”。
7. 薪资不披露就不猜；推算值必须显式标记。
8. 历史风险必须有来源、有日期、有范围；社区传闻不得冒充事实。
9. 不虚构岗位、JD、候选人经历、官方投递地址或公司历史事件。
