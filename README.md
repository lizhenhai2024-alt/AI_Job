# AI Job

面向 **2027 届校招** 的岗位发现 / 情报库。

> **仓库职责已经固定：**
> - `AI_Job`：负责岗位发现、来源核验、交叉取证、去重、职位级链接、届别/截止/语言要求等情报线索。
> - `campus-job-board`：负责最终岗位判断与展示。
> - **S/A/B、匹配度、岗位方向、公司匹配度、是否值得投，全部以 Vercel「2027届校招机会看板 · 英语专业」的规则为准。**

最终看板：<https://campus-job-board-mu.vercel.app/>

## AI_Job 不再做什么

本仓库不再维护第二套候选人匹配算法，也不再输出：

- S / A / B 等级
- 0–100 匹配度
- 最终岗位方向
- 公司匹配度
- “优先投 / 可以投 / 不建议投”等最终结论

这样可以避免两个仓库分别计算、结果冲突。

## 当前核心能力

- 多源自动岗位发现
- 2027 届岗位线索识别
- 截止 / 关闭状态识别
- 公司、岗位、城市标准化
- 技术岗等明显噪音过滤
- 岗位抓取标签（仅用于发现，不作为最终岗位方向）
- 官方源 / 二手源区分
- 来源渠道归类
- 情报完整度检查
- 小语种硬要求线索识别（只提示，最终由看板判定）
- 公司发现队列 / ATS 来源发现
- `src/data/live-jobs.js` 作为最终看板的数据输入之一

## 五大获取渠道

1. **公司官方校招官网 / ATS 系统**  
   飞书招聘、Moka、北森、智联校招、牛客校招、公司自建招聘官网等。
2. **高校就业信息网官方简章**  
   南开大学、广东外语外贸大学、对外经贸大学、湖南大学、厦门大学等 30+ 高校。
3. **招聘平台官方账号**  
   猎聘、51job、智联招聘、应届生求职网。
4. **牛客 / 脉脉官方内推帖**
5. **公司官方公众号 / 微博校招公告**

渠道配置见：`config/source-channels.json`。

## 数据处理原则

```text
五大渠道发现
    ↓
保留原始来源与职位链接
    ↓
2027 届 / 截止 / 关闭状态校验
    ↓
Job Schema 标准化
    ↓
明显噪音过滤 + 抓取标签
    ↓
跨来源核实 / 去重 / 来源证据保留
    ↓
src/data/live-jobs.js
    ↓
campus-job-board
    ↓
最终 S/A/B、匹配度、岗位方向、公司匹配度、是否值得投
```

### 来源规则

- **官方职位级来源优先。**
- 高校就业网、招聘平台、内推帖、公众号/微博可作为发现入口和补充证据。
- 二手或公告级来源不能替代职位级官网核验。
- 同一岗位多源出现时，应保留交叉证据，而不是简单丢掉所有重复来源信息。
- 投递链接优先指向公司官方校招官网 / 官方 ATS 的具体职位页面。

## 自动刷新

```bash
npm run refresh:jobs
npm run check
```

GitHub Actions 每日自动刷新岗位池。只有岗位池实际变化时才提交新的 `src/data/live-jobs.js`。

## 设计底线

1. **发现准确性** 与 **最终判断准确性** 分开治理。
2. `AI_Job` 宁可多保留可核验情报，也不擅自给最终求职结论。
3. `campus-job-board` 是最终裁决层，AI_Job 不反向覆盖看板规则。
4. 正式岗位必须可追溯；来源不充分就明确标记“待官网复核”。
5. 不虚构岗位、JD、候选人经历或官方投递地址。
