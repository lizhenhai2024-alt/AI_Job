# AI Job

面向 **2027 届校招** 的公司/岗位自动发现、可解释匹配与投递管理工具。

> 核心问题：**今天又有哪些公司开始招人？其中哪些岗位最值得优先投？为什么？**

## 当前能力

- **多源自动岗位发现**：每天自动扫描公开校招索引、ATS 门户和公司官方招聘接口
- **官方源优先**：已接入 Moka、北森以及安克创新、EcoFlow 官方招聘数据源
- **广泛发现补充**：使用牛客公开职位做二手广泛发现，并明确标记“二手来源，待官网核验”
- **2027 届筛选**：自动识别届别、截止状态、关闭状态并过滤过期岗位
- **技术岗强排除**：避免“电商系统开发工程师”等仅因关键词相似而误入推荐
- **岗位分类**：覆盖 GTM、产品运营、产品营销、海外运营、电商运营、用户运营、业务运营、内容运营、项目管理、HR、市场、销售等岗位族
- **相邻岗位语义归类**：例如社媒/KOL → 内容运营，品牌经理/品牌管理 → 产品营销，服务运营/部门运营 → 业务运营
- **公司雷达**：从真实岗位池反推正在招聘的公司、城市、岗位族和最高匹配度
- **岗位雷达**：支持关键词、城市、岗位族、最低匹配分筛选
- **0–100 可解释匹配**：岗位方向、技能、城市、经历、语言、届别、偏好 7 个维度
- **分层推荐**：高分二手来源不会直接进入最高等级，官方来源才能获得最高可信推荐等级
- **高匹配亮点 / 能力缺口 / 风险提示**
- **投递看板**：推荐 → 已收藏 → 已投递 → 面试 → Offer → 淘汰
- **候选人画像**：目标岗位、城市、技能、语言、经历关键词、职业偏好与硬性排除条件
- **本地存储**：画像和投递状态保存在浏览器 `localStorage`
- **自动测试**：覆盖抓取、标准化、分类、去重、匹配和来源可信度等核心逻辑

## 数据源架构

```text
牛客公开职位（广泛发现，二手）
Moka 官方校招门户
北森官方校招门户
安克创新官方招聘接口
EcoFlow 官方招聘接口
            ↓
        多源岗位发现
            ↓
  2027 届别 / 截止 / 关闭状态校验
            ↓
      Job Schema 标准化
            ↓
   岗位分类 / 技术岗强排除
            ↓
       去重 / 来源保留
            ↓
    src/data/live-jobs.js
            ↓
   浏览器中的个人画像精排
            ↓
     岗位雷达 / 公司雷达
```

### 当前来源策略

- **牛客**：承担广覆盖发现。属于二手公开来源，界面会明确标记，并要求正式投递前回公司官网核验。
- **Moka / 北森**：从公开校招门户发现官方岗位，保留官网来源信息。
- **安克创新 / EcoFlow**：使用公开官方招聘接口获取岗位，保留官方来源与职位链接。
- 来源临时失效或没有新结果时，系统会尽量保留上一版有效岗位池，避免页面被异常清空。

## 搜索与推荐为什么分两层

后台自动刷新无法读取浏览器 `localStorage` 中的个人画像，因此搜索分成两层：

- `config/search-profile.json`：后台使用的**宽搜索配置**，目标是尽量不漏掉运营、市场、GTM、电商、项目、HR、英语/海外等相邻机会。
- `src/data/profile.js` / 浏览器画像：前端使用的**个性化精排配置**，决定哪些岗位更适合当前求职者。

后台当前采用保守并发策略，优先保证岗位召回完整性，不以更高抓取速度换取静默漏岗风险。

## 自动刷新

手动运行：

```bash
npm run refresh:jobs
```

完整检查：

```bash
npm run check
```

GitHub Actions：`.github/workflows/job-refresh.yml`

- 每天 UTC 00:15 自动刷新（中国 / 新加坡时间约 08:15）
- 支持 Actions 手动触发
- 自动刷新完成后运行静态检查与测试
- 只有岗位池实际变化时才提交新的 `src/data/live-jobs.js`
- 仅保存标准化摘要和来源元数据，不在仓库中复制完整 JD

## 本地运行

## GitHub Pages 部署

仓库已经提供 `.github/workflows/pages.yml`，但 **GitHub Pages 需要在仓库设置中一次性启用**。

1. 打开仓库 `Settings` → `Pages`
2. 在 `Build and deployment` 下将 `Source` 设为 **GitHub Actions**
3. 回到 `Actions` → `Deploy GitHub Pages`
4. 点击 `Run workflow`

启用后即可把当前静态应用作为在线求职工具使用。

## 数据与安全原则

1. 候选人画像是生成内容的唯一事实源，不虚构经历。
2. 先判断“值不值得投”，再生成材料和推进投递。
3. 正式岗位必须保留可追溯来源；二手来源明确标记并要求官网复核。
4. 自动检索只访问公开页面 / 公开接口，不绕过登录、验证码或访问控制。
5. 默认不替用户自动投递或发送消息。
6. 数据采集与 AI 匹配解耦，任一层都能独立升级。
7. 岗位召回完整性优先于抓取速度。
